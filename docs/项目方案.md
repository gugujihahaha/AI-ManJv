# 漫剧工厂 ManJv Factory

> **一条从剧情文本到竖屏漫剧视频的 AI 生成流水线**

| 项 | 内容 |
|---|---|
| 项目代号 | AI-ManJv |
| 文档状态 | 方向定稿 v3 |
| 更新日期 | 2026-09-15 |
| 课程 | 软件应用开发实践（第 2—17 周） |
| 定位 | 课程项目，非商业产品 |

---

## 1. 一句话定位

输入一段剧情文本，输出**一条 9:16 竖屏漫剧视频 + 一份可继续编辑的工程**——有剧情、有配音、有画面、有字幕，能直接播放，也能在剪辑软件里继续改。

从脚本改编、镜头切分、画面生成，到配音、配乐、运镜、字幕、合成、导出，**全链路在一个网页里自动跑完**，无需在多个工具之间手工搬运。

> **交付物是"这条线"，不是"一条爆款片"。**
> 目标是证明这条流水线能跑通、能稳定产出，而不是追求单条作品的观感。

> **成片不是终点。**
> 流水线内部始终持有一份完整的**时间线数据结构**（每格用哪张图、多长、什么运镜、配什么音、字幕是什么）。
> 成片 mp4 只是这份数据的一种渲染输出——**导出可编辑工程，是同一份数据换个格式再渲染一次**。

## 2. 为什么做这个

### 2.1 现状：工具是割裂的

今天做一个 2 分钟的 AI 漫剧短视频，真实流程是这样的：

```
ChatGPT 拆分镜
  → 逐个复制提示词到即梦 / Midjourney 出图
    → 一张张下载
      → 剪映里配音、配乐
        → 手动对齐字幕
          → 导出
```

五个工具，全靠**手工搬运**。真正花在创作上的时间远少于花在搬运上的时间。

### 2.2 核心痛点

| # | 痛点 | 后果 |
|---|---|---|
| 1 | **工具割裂** | 没有一条打通的链路，搬运本身就是主要工作量 |
| 2 | **角色形象跳变** | 换个镜头就换张脸，观众出戏 |
| 3 | **黑盒不可改** | 现有 AI 工具一次生成全错，只能重来 |
| 4 | **门槛叠加** | 要同时会写提示词、会剪辑、会调音 |

> **关于痛点 2 的项目决策**：角色跨图一致性是 AI 漫画领域公认未解决的难题，投入产出比极低。
> 本项目**不把它作为目标**，仅采用提示词层面的轻量缓解（见 5.2）。这是明确的范围取舍，不是能力缺口。

### 2.3 核心价值

> 把「穿梭在五个工具之间手工搬运」变成「一个网页里从文本走到成品」。
> **并且成品是开放的**——可以继续改，而不是一个锁死的 mp4。

**可观察的前后变化：**

| | 之前 | 之后 |
|---|---|---|
| 产出方式 | 5 个工具手工搬运 | 1 个网页端到端 |
| 单条耗时 | 数天 | 数小时 |
| 人工介入 | 全程手工 | 仅分镜确认一个环节 |
| 成品修改 | 回五个工具重来 | 导出工程，在剪映里改 |

## 3. 目标用户

### 主要用户：个人漫剧创作者

| 维度 | 描述 |
|---|---|
| 目标 | 把已有的文字内容快速转成可发布的漫剧视频 |
| 能力 | 有内容 sense，但**不会画画**，剪辑与提示词技能有限 |
| 环境 | 单机作业，预算有限，消费级硬件 |
| 痛点 | 见 2.2 四条 |

## 4. 生产线全景

整条线 **13 环**，按优先级分三档：

- 🟥 **核心**——不跑通就没有成品
- 🟨 **增强**——零成本或低成本，对观感提升明显
- 🟩 **可选**——有余力再做

| # | 环节 | 实现方式 | 由谁决策 | 优先级 |
|---|---|---|---|---|
| ① | 剧情文本输入 | — | 用户 | 🟥 核心 |
| ② | 脚本改编与镜头切分 | LLM | LLM | 🟥 核心 |
| ③ | **分镜确认** | 前端（轻量） | **人工** | 🟥 核心 |
| ④ | 逐格画面生成 | 文生图 | 图像模型 | 🟥 核心 |
| ⑤ | 配音（多角色音色 + 情绪） | TTS | LLM 指定 + TTS 执行 | 🟥 核心 |
| ⑥ | 字幕生成 | 按配音文本切分 | 参数驱动 | 🟨 增强 |
| ⑦ | 音画同步（每格时长 = 该格配音时长） | 参数驱动 | 参数驱动 | 🟨 增强 |
| ⑧ | 运镜（推 / 拉 / 摇 + 时长） | LLM 出参数 + ffmpeg `zoompan` | LLM | 🟨 增强 |
| ⑨ | BGM（情绪驱动选曲） | 素材库 + LLM 情绪打标 | LLM | 🟨 增强 |
| ⑩ | 口型开合 | librosa 音量包络 + ffmpeg 贴图 | 音频驱动 | 🟩 可选 |
| ⑪ | 音效 SFX | 素材库 + LLM 按画面匹配 | LLM | 🟩 可选 |
| ⑫ | 合成 9:16 成片 | ffmpeg | 参数驱动 | 🟥 核心 |
| ⑬ | **导出可编辑工程** | 时间线数据 → 剪映草稿 / 素材包 | 参数驱动 | 🟥 核心 |

## 5. AI 必要性分析

### 5.1 核心架构论点

> **这条线里有两类工作：判断 和 执行。**
> **判断交给 AI，执行交给确定性引擎。**

这是整套设计的骨架，也是本项目 AI 必要性的根本论证。

**AI 负责判断（无固定规则可循）：**

- 这段剧情该切成几个镜头？在哪里切？
- 这一格该用远景还是特写？画面里有什么？
- 这句台词该用什么情绪、什么音色念？
- 这一格该推近还是拉开？停留几秒？
- 这段该配什么情绪的音乐？

以上没有一条能写成 if-else 规则。

**确定性引擎负责执行（不需要 AI，也不该用 AI）：**

- 按参数把静态图做平移缩放
- 按时间轴对齐音轨
- 把字幕烧进画面
- 合成视频、导出工程文件

用 AI 做这些，只会更贵、更慢、更不可复现。

### 5.2 角色形象：轻量处理，不作为目标

跨图角色一致性是行业未解决难题（精确驱动对动漫脸效果差，训练 LoRA 的成本与数据量都不是课程项目能承担的）。

**本项目采取的策略：**

| 做法 | 成本 | 说明 |
|---|---|---|
| 角色卡提示词注入 | 极低 | LLM 提取角色外貌描述，固定注入每一格提示词 |
| 固定 seed | 极低 | 同项目内保持一致即可 |

**明确不投入**：参考图图生图调优、角色 ID / IP-Adapter、模型微调。

> 这是**主动的范围取舍**：把节省的时间投入到 5.3 的质量杠杆上，收益更高。

### 5.3 质量杠杆（省下的时间投这里）

按对最终观感的影响排序：

| 排序 | 杠杆 | 成本 | 为什么值得 |
|---|---|---|---|
| 1 | **分镜拆分质量** | 提示词迭代 | 直接决定"有没有剧情"，是最核心的质量项 |
| 2 | **配音质量** | 零成本 | 音色选择、语速、情绪、多角色区分，决定"像不像漫剧" |
| 3 | **运镜** | 零成本 | 把"幻灯片"变成"视频"，投入产出比最高的一项 |
| 4 | **音画同步** | 零成本 | 每格时长严格等于该格配音时长，是"专业感"的关键 |
| 5 | 字幕 | 零成本 | 完成度 |
| 6 | BGM | 零成本 | 情绪与节奏 |

**3、4 两项加起来不到 10 小时，但能把成品从"能看"抬到"像样"。**

### 5.4 为什么不做图生视频

| 方案 | 成本 | 可控性 | 可复现 |
|---|---|---|---|
| A. 图生视频 API（可灵 / 即梦 / Vidu） | 每 5 秒数元，一条 2 分钟漫剧上百元 | 低 | 否 |
| B. **2.5D 确定性运镜**（ffmpeg `zoompan`） | **0 元** | 高 | 是 |

**选 B。** 关键在于：**运镜的执行是确定性的，但"该用什么运镜"是导演判断，由 LLM 决定。** AI 出决策，引擎执行——AI 必要性不减反增，同时成本归零、结果可复现、方便验收。

## 6. MVP 边界

### 6.1 🟥 核心闭环（必做，第 6 周前跑通）

> 输入剧情文本
> → LLM 切成 8—12 个镜头
> → 分镜确认（轻量人工介入）✅
> → 逐格生成画面
> → 逐格配音
> → 合成 9:16 竖屏 mp4

**目标：产出一条"有剧情、有配音、能播放"的视频。** 画面质量不设门槛。

### 6.2 🟥 开放输出（第 7—9 周）

**用户必须能拿回去自己改**，这是产品定义的一部分，不是附加功能。

三种输出，都是**同一份时间线数据的渲染**：

| 输出 | 用途 | 实现成本 | 风险 |
|---|---|---|---|
| **9:16 成片 mp4** | 直接发布 | 已含在核心闭环 | 低 |
| **分层素材包 + 时间线清单** | 兜底，可导入任意剪辑软件 | 4—8h | 低 |
| **剪映草稿工程** | 双击打开即是拼好的时间线，直接改 | 8—15h | 中（格式兼容） |

**实施顺序**：先做素材包（无风险、稳），再攻剪映草稿（收益大、有兼容风险）。

配合**局部重跑**能力：用户看到第 5 格不满意 → 改提示词 → 只重跑该格 → 重新合成。这比导出后手工替换更省事。

### 6.3 🟨 质量增强（第 10—14 周逐项叠加）

按 5.3 的杠杆排序推进：分镜质量 → 配音质量 → 运镜 → 音画同步 → 字幕 → BGM。

每加一项都是一次独立提交，随时可停。

### 6.4 🟩 可选（有余力）

口型开合、音效 SFX、更精细的配音情绪控制。

### 6.5 明确不做

| 不做的事 | 原因 |
|---|---|
| **系统内可视化编辑器** | 用「导出到剪映」以 1/3 成本满足同样需求（见 §12 第三次调整） |
| **跨图角色一致性** | 行业未解决，投入产出比极低（见 5.2） |
| **精确 lip-sync** | 真人数据训练，对动漫脸效果差 |
| **AI 作曲** | 用无版权素材库 + LLM 情绪选曲替代 |
| **真·图生视频** | 成本不可承受、结果不可复现 |
| **长篇小说全本改编** | 只做单段 / 单章 |
| **多用户、团队协作、版权管理** | 非本学期范围 |

### 6.6 怎么算做成了

| 维度 | 验收标准 |
|---|---|
| 端到端 | 给定一段文本，产出一条完整可播放的 9:16 mp4 |
| 有剧情 | 人工判断：分镜是否讲清了原文的故事 |
| 有配音 | 每格都有对应配音，多角色音色可区分 |
| 音画同步 | 画面切换与配音节奏对齐 |
| 一条线 | 全程在单一页面内完成，无需外部工具 |
| **可再编辑** | **导出的工程能在剪映中打开，且各轨道（画面 / 配音 / 字幕 / BGM）可独立调整** |

## 7. 差异化

### 7.1 现有方案对照

| 现有方案 | 能力 | 不足 |
|---|---|---|
| Midjourney / SD + 手写提示词 | 单图质量高 | 不会拆分镜；要求用户会写提示词 |
| 即梦 / 可灵等一站式平台 | 功能全 | 黑盒、贵、不针对"文本改编"场景；**成品难以二次编辑** |
| 剪映等剪辑工具 | 剪辑强 | 只有后期，不含生成 |
| 人工约稿 | 质量最好 | 周级交付、百元/格 |

### 7.2 本项目的差异

> **全链路打通，且成品是开放的。**

三层可介入：

1. **生成前**——分镜脚本可编辑
2. **生成中**——单格可改提示词后局部重跑
3. **生成后**——导出工程，在专业剪辑软件里继续改

生产线最怕"全自动黑盒"，一次生成全错只能重来。**每一层都能人工顶上去。**

## 8. 技术选型

| 环节 | 选型 | 说明 |
|---|---|---|
| 后端 | Python 3.13 + FastAPI | 已有 v0.1.0 骨架 |
| 存储 | SQLite | 表：projects / shots / assets / renders |
| 大语言模型 | DeepSeek | 负责分镜、角色卡、运镜参数、配乐情绪，**全部结构化 JSON 输出** |
| 图像生成 | 即梦 / 通义万相 / 豆包 API，或本地 SD | 本地 SD 免费但需显卡 |
| 语音合成 | **Edge-TTS** | 免费、中文音色多、可按角色分音色 |
| 运镜 | ffmpeg `zoompan` 滤镜 | 推拉平移，参数化可复现 |
| BGM / 音效 | 无版权素材库 + LLM 情绪打标 | 零成本 |
| 口型 | librosa + ffmpeg | 音量包络驱动嘴部图切换（可选） |
| 合成 | ffmpeg | 9:16 竖屏、字幕烧录 |
| **工程导出** | **pyJianYingDraft**（剪映草稿）+ 自定义素材包 | 剪映草稿格式为逆向工程，需锁定版本 |
| 前端 | 原生 HTML + JavaScript | 轻量，无构建链 |

## 10. 风险与降级预案

| 风险 | 概率 | 降级方案 |
|---|---|---|
| 剪映草稿格式兼容失败 | 中 | 退回素材包导出（无风险路径） |
| 图像生成费用超预算 | 中 | 换本地 SD；或降低单集镜头数 |
| 分镜质量不理想 | 中 | 迭代提示词；或提供多套模板供选择 |
| 合成环节进度落后 | 中 | 降级为「分镜包 + 配音包导出」 |
| 口型贴图对不齐 | 中 | 直接跳过（本就是 🟩 可选） |

> **终极降级方案**：若合成环节整体不达标，退化为「分镜脚本 + 配音生成器」。
> 这是本项目的**非 AI 降级路径**，降级后仍是一个完整可用的产品。

## 12. 附：方向演进记录

本项目方向经过**三次**重要调整，此记录用于课程实验 2.4「需求变化说明」。

### 第一次：去模糊化

| | 调整前 | 调整后 |
|---|---|---|
| 名称 | AI 漫剧创作系统 | 漫剧工厂 ManJv Factory |
| 范围 | 全流程，无明确边界 | 流水线，边界清晰 |
| 交付物 | 模糊（"漫剧作品"） | 明确（生产线 + 一条成片） |

### 第二次：去高风险项

| | 调整前 | 调整后 |
|---|---|---|
| 角色一致性 | 列为核心技术点 | **主动放弃**，仅做提示词轻量缓解 |
| 工期估算 | 143—217h | 90—128h |

**原因**：角色一致性投入 15—25 小时仍不保证结果，风险与收益严重不匹配。

### 第三次：换实现路径，不砍需求

| | 调整前 | 调整后 |
|---|---|---|
| 二次编辑能力 | 系统内可视化编辑器（25—40h） | **导出剪映草稿 + 素材包**（12—23h） |
| 成品可编辑性 | 依赖自研编辑器 | 借力成熟剪辑软件，能力强得多 |
| 定位 | 附加功能 | **提升为核心交付物**（🟥） |

**原因**：用户需要的是"能改"，不是"用你的编辑器改"。自研编辑器是过度设计。
把时间线条数据结构多写一个导出器，成本约为自研编辑器的 1/3，而剪映的编辑能力远超课程项目能实现的上限。

**三次调整的共同逻辑**：
> 每一次都不是简单地"砍需求"，而是**找到一个更便宜的路径去满足同一个需求**。
> 第二次砍掉的是目标（角色一致性），换来了质量杠杆的投入空间；
> 第三次砍掉的是实现方式（自研编辑器），需求本身反而升级成了核心交付物。
