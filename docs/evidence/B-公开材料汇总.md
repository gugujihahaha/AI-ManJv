## 二、按四类痛点归拢（报告 §2.1.2 要用的结构）

### ① 工具割裂 —— 环节分散在多个平台，靠人工搬运

**待核对引文：**

- 市面多数制作流程为「写剧本 → 拆分镜 → 抽卡生成角色 → 逐镜头生成视频 → 手动拼接剪辑 → 配乐字幕」，每个环节都可能用了 AI 工具，**但都需要人工介入**。（来源：DataEye 研究院，见 P-09 / P-01）
- 影视团队调研描述的真实工作流：用大模型写剧本提示词 → 切换到 A 工具做人设图 → 跳到 B 工具做场景 → 用 C 工具生成视频素材 → 在 D 软件里剪辑 → 跑到 AE 做特效 → 用网盘传输、用微信群统筹。**单项工具都很强，但连起来非常繁琐。**（来源：MovieFlow Studio 团队调研）
- 素材与版本混乱：脚本散在便签、文档、聊天记录里，生成的片段存了十几个文件夹，改完脚本要来回传微信。（来源：今日头条工具梳理文章）
- 常见工具分工：分镜原画用即梦、静态转动态用可灵、特效镜头用 Pika、后期调整用 Runway、配音用海螺 AI、最终整合用剪映、协作中枢用扣子——**7 个工具**。

### ② 角色形象跳变 —— 跨镜头一致性

**待核对引文：**

- 观众原话：「十个女主九个都是同款尖下巴大眼睛，连笑起来的弧度也一模一样，**好几次看一半实在忍不了，就划走弃剧了**。」（来源：P-03 / P-04，受访观众李女士）
- 「上一秒是藏獒，下一秒变柴犬」，被从业者评价「根本没法看」。（来源：P-02）
- 一致性是最大难点：设计一张新脸不难，难的是同一角色在侧脸、远景、不同光线、不同情绪下都不能"变成另外一个人"。一个主要角色可能要花数小时甚至更长确认。
- 完播率从 42% 降至 19%；「AI 脸」引发"生理性厌恶"登上热搜。

> ⚠️ 这一条是**你明确不解决的问题**。报告里的用法是：承认它是行业公认难题，然后说明这是**主动的范围取舍**（见 §2.3.2 和项目方案 §5.2），而不是能力缺口。

### ③ 成品不可修改 —— 只能重抽

**待核对引文：**

- 「输入同样的内容，可能输出完全不同的结果，有时惊艳，有时翻车」，同一镜头反复生成十几遍、几十遍是常态，**不存在一次生成就能直接使用的画面**。（来源：P-07）
- 从业者原话：「抢救的话把有用的备注留下来，**废片中实在不能用的片段独立重抽**」。（来源：LINUX DO 论坛，P-11 相关）
- 早期 AI 生成画面可用率仅 20%—30%；全行业 **40%—50% 的返工工作量集中在"修正穿帮"**上。（来源：P-08）
- 某头部漫剧团队一分钟成本约 1.5 万元，100 分钟项目需 150 万元，最终项目暂停。（来源：P-08）
- 案例：一集制作周期约 10 天、成本约 1 万元，**一个几秒的镜头曾尝试四五十次**。（来源：P-06）

### ④ 门槛叠加 —— 会写提示词 + 会剪辑 + 会调音

**待核对引文：**

- 导演总结：「**AI 降低的是执行门槛，抬高的是内容门槛**」——抽卡、剪辑培训几天就能上手，但编剧、叙事把控 AI 替不了。
- 「AI 降低的从来不是'做好内容'的成本，**它降低的是'做出来'的成本**。」
- 《AI 导演手册》一书单人完成 AI 短剧闭环，需涉及 **18 个工具**（3 款脚本编写、9 款图像视频生成、6 款剪辑音频）。

## 四、⚠️ 重要发现：一站式平台已经出现（影响 §2.3 立论）

检索中发现了**四个已经在做"打通全链路"的方案**，其中三个是商业平台：

| 平台 | 已具备的能力 | 仍未解决 |
|---|---|---|
| **腾讯云创意工坊** | 无限画布整合多模型（混元 / 即梦 / 可灵 / Vidu / 海螺 / 千问 / Google）+ Agent 集群；自动把分镜视频铺到时间线；**在线非线性编辑**；合成导出 4K/2K | 云端商用服务，素材需上传；编辑在平台内，**拿不回本地工程文件** |
| **PixTV AI** | 脚本 / 图像生成 / 视频生成 / 声音 / 音乐 / 素材管理 / 剪辑纳入同一空间 | 同上 |
| **MovieFlow Studio** | 剧本解析 → 分镜 → 影像生成 → 时间线剪辑收进一个工作台；宣称步骤减少 70%、Token 降 70%、角色统一度 95% | 同上 |
| **Jellyfish**（GitHub 开源） | 剧本输入 → 智能分镜 → 角色/场景一致性管理 → AI 视频生成 → 后期剪辑 → 一键导出 | 面向视频生成，非竖屏漫剧工作流 |

### 这对本项目的三个影响

1. **"打通链路"这个方向被市场验证了** —— 对你的立论有利：说明方向判断没错。
2. **但"打通"本身不再是差异点** —— 报告 §2.3 不能再说"现有方案都是黑盒、割裂"。
3. **差异点要重新表述**：

> 面向个人创作者、**单机部署、文本不进第三方平台**；成品以**剪映草稿**形式落到本地，
> 用户用自己已经熟悉的专业剪辑软件继续改，**不被平台锁定**。

### 同时，这一节正好补上老师的要求

老师 §2.3 明确要求「**总结现有方案中可以借鉴的设计和仍未解决的问题**」——这批材料就是现成的答案：

- **可借鉴的设计**：MovieFlow Studio 把「一致性管理」做成资产库的思路；腾讯云的「分镜视频自动铺时间线」；Jellyfish 的「一键导出」。
- **仍未解决的问题**：全是云服务，个人创作者要么付费用量、要么把剧本上传；成品仍在平台内闭环。
